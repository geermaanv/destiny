- **`A1-datos-natales` implementada**: tabla `profiles` (SQLAlchemy, `create_all` sin migraciones todavía), endpoints `POST /profiles`, `POST /profiles/{id}/birth-data`, `GET /profiles/{id}` en `apps/api`; pantalla `/onboarding/datos-natales` en `apps/web` (formulario + botón "No sé mi hora exacta"). Validado end-to-end con Postgres local real y con Playwright contra ambos servidores corriendo: hora exacta se persiste, hora desconocida asigna `12:00` + `birth_time_estimated: true`, geocoding de `birth_place` queda fuera de alcance (lat/lon/timezone opcionales).
- Fix de CORS en `apps/api` (faltaba permitir `127.0.0.1:3000` además de `localhost:3000`).
- Nota de entorno: en esta sesión Docker no estaba disponible (sin daemon); se usó el Postgres 16 ya instalado en el sistema como servicio para validar. `docker-compose.yml` sigue siendo el camino recomendado en una máquina con Docker.
- **`A2-ritmo-notificaciones` implementada**: campo `notification_rhythm` en `Profile`, endpoint `POST /profiles/{id}/notification-preference` (valida `ritmo_diario`/`pulso_cosmos` con Pydantic `Literal`, 422 en cualquier otro valor), pantalla `/onboarding/ritmo-notificaciones`.
- **`A3-verificacion-identidad` implementada**: `app/adapters/kyc.py` con el `Protocol IdentityVerificationAdapter` (ADR 0006) y un `MockKYCAdapter` que resuelve los 4 estados finales para testing sin vendor real; endpoints `POST`/`GET /profiles/{id}/verification`; pantalla `/onboarding/verificacion` (captura vía `<input type="file" capture="user">`, funciona como selfie en mobile y como file picker en desktop/testing).
- **Onboarding completo validado end-to-end**: A1 → A2 → A3 encadenado (cada paso redirige al siguiente con `profileId` en la URL), probado con Playwright contra Next dev + FastAPI + Postgres reales, terminando en estado `verificado`.
- Se intentó exponer el proyecto corriendo en este contenedor a una URL pública (túnel) para que Pablo pudiera verlo sin estar en la misma red — **bloqueado por política de la plataforma** (clasificador de Claude Code deniega "External Ingress Tunnel" desde este entorno cloud). No reintentado por otra vía. Opciones reales para que Pablo vea el avance quedan pendientes de decidir con él: correr local + túnel desde la máquina de alguien del equipo, o un hosting propio (ver conversación — VPS chico corriendo el mismo `docker-compose.yml`, o Vercel/Render/Railway).
- **`B4-home-tu-momento` implementada**: `app/astro.py` usa `astronomy-engine` (ADR 0005, primera vez que se usa para cálculo real) para fase lunar + signo zodiacal, cacheado por día (`lru_cache`). Modelo `MoodCheckin`. Endpoints `GET /home/today`, `GET /home/frequency-count` (heurística v1: cuenta perfiles `verificado`, sin agrupación geográfica todavía — ver fuera de alcance de la spec), `POST /mood-checkins`. Pantalla `/home` conectada como destino final de la verificación exitosa en el onboarding (A3 → Home).
- **`B5-pantalla-descubrir` implementada**: `app/compatibility.py` calcula el aspecto Sol-Sol real entre dos cartas (`astronomy-engine`, simplificación v1 — solo Sol, documentado en el código y en `BACKLOG.md`) y deriva un % de compatibilidad determinístico. `app/explainer.py` agrega un segundo adapter con el mismo patrón que KYC (ADR 0006): `ClaudeResonanceExplainer` (real, Claude API) si `ANTHROPIC_API_KEY` está configurada, si no `MockResonanceExplainer` con copy editorial borrador — no hay key en ningún entorno todavía, así que hoy corre en modo mock. Endpoints `GET /discover` (gating por verificación, 403 si no `verificado`) y `GET /discover/{id}/explanation`; pantalla `/discover` (lista + % + explicación al abrir). `anthropic` sumado a `requirements.txt` (ya decidido en ADR 0004, se integra ahora detrás del adapter). Validado end-to-end con perfiles reales en distintas fechas natales (conjunción, cuadratura, oposición) y con el caso 403 de perfil no verificado.
- **`B6-calendario-memoria` implementada**: `app/aspects.py` (extraído de `compatibility.py` para compartir la clasificación de aspectos) + `app/transits.py` (Luna del día vs. Sol natal del usuario, misma simplificación v1 que `B5`). Modelo `CalendarAnnotation`. Endpoints `GET /calendar/{year}/{month}`, `GET /calendar/day/{day}`, `POST /calendar/day/{day}/annotations`. Nota de implementación: hubo que reordenar las rutas en `app/routers/calendar.py` — `/day/{day}` matcheaba como `/{year}/{month}` por orden de registro en FastAPI; las rutas literales van primero. Pantalla `/calendario` (grilla mensual con tránsitos marcados, detalle de día + anotaciones). Validado end-to-end con Playwright.
- **`B7-chat-rompehielos` implementada**: `app/icebreaker.py`, tercer adapter con el mismo patrón que KYC (ADR 0006) y el explainer de B5 (mock sin `ANTHROPIC_API_KEY`, `ClaudeIcebreakerGenerator` real con ella). Modelos `Match` y `ChatMessage`. `POST /matches` crea el match y genera + inserta el primer mensaje automáticamente (basado en `compatibility_signals`, igual que B5); `GET`/`POST /chats/{match_id}/messages`. Pantalla `/chat/[matchId]`, con botón "Match" sumado a `/discover` para cerrar el flujo completo descubrir → match → chat. Con esto, **Módulo B completo**. Validado end-to-end con Playwright.
